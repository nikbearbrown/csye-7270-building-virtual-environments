# Planning checks: results

**What this is.** The runs behind the numbers in `FACTCHECK.md`, in the order they were done, with the script, the log, the result and what it means. All on Bear's Mac: Apple M4 Pro, Godot 4.7.2 stable (official), Forward+ unless stated, 2026-10-13. Every script was also run on the Compatibility renderer (`*-compat.log`).
**Why.** So any figure on screen can be re-run, and so the failed and inconclusive runs stay visible and labelled.
**Found.** Nine scripts, one Lab batch, one capture-scene library. Seven runs did not give the answer first time (a parse error, probe bugs, a wrong baseline, stale names after the timeline changed, a hung script, a run against an earlier hand-timed file, a coarse 8-bit decode) and all are kept. Four findings changed the film: an empty `light()` leaves the ambient look, the one-line copy of the default is exact but ignores normal maps, `LIGHT_DIRECTION` points from the pixel toward the lamp, and screen-space numbers are physical pixels (so the captures cannot use the 3x SubViewport route).

How to re-run (nothing here writes into the film folder except this evidence): copy this folder to a scratch place (the first run creates a `.godot` cache), then
`godot --path <copy> [--rendering-method gl_compatibility] --script res://verifyN.gd` for N = 1 to 7, and
`godot --path <copy> --script res://verify8_captures.gd -- <abs lab-shaders> <abs captures.json>` and `... verify9.gd -- <abs lab-shaders> <abs captures.json>`.
Reads come from the root viewport (or a 1920 x 1080 SubViewport) as 8-bit colour, so every value is quantised to 1/255 = 0.004. The machine was shared with other Godot sessions, so wall-clock numbers (the tween reads) wobble; the values they report do not.
