# Planning checks: results

**What this is.** The runs behind the numbers in `FACTCHECK.md`, with the command, the result and what it means. All on Bear's Mac: Apple M4 Pro, Godot 4.7.2 stable (official), Forward+ unless stated, 2026-10-13.
**Why.** So any figure on screen can be re-run. Failed runs are kept and labelled. For every measured value the expected value was derived independently in Python (never copied from the shader), and every unit-test strip carries negative controls that must come out red.
**Found.** One driver, `geometry_checks.py`, runs 61 checks through the Shader Lab (`check_shader.sh`) in about a minute and prints PASS or FAIL for each (all PASS); three GDScript scratch checks cover what the Lab cannot (rotation direction against Godot's own `Node2D.rotation`, where `VERTEX` starts, driving the flip from the game); one scale check proves the 4K plan (a 1024 px card with every pixel uniform times eight) draws the same picture. Two runs did not pass first time and are kept: a typing error in a scratch script, and the two compile errors that were meant to happen.

Re-run everything: `python3 geometry_checks.py` (writes `lab-results.jsonl`, `geometry-summary.txt`, `png/`). Re-run a GDScript check: copy `project.godot` and the `verify*.gd` file into an empty directory and run `godot --path <dir> --script res://<file>.gd` (non-headless; `verify3` reads `lab-shaders/11-door.gdshader` by absolute path, set at its top). Planning stills: `python3 make_planning_stills.py`. Scale check: `python3 scale_invariance_check.py`.

**Note on exploratory runs.** Before the driver existed, the first versions of the three unit strips (eight, eight and fourteen rows) and a handful of single renders were run by hand while the shaders were being designed; all gave the same values the driver now records, and the strips were then extended (more rows, negative controls) and re-run through the driver, which is the saved record. Nothing was dropped because it disagreed.

**What the Lab cannot do, and how it was covered.** It cannot compare against Godot's own node rotation, move a sprite's `centered` flag, or call `set_shader_parameter` from a script: `verify1`, `verify2` and `verify3` do those in a scratch project. It renders at 640 x 360; the 4K plan is covered by the scale check. Pixel values are 8-bit (so a colour such as (0.3686, 0.6392, 0.5686) is the rounded teal), which is why the table check compares with `==` inside the shader instead of reading a number back.
