# Planning checks: results

**What this is.** The runs behind the numbers in `FACTCHECK.md`, with the command, the result and what it means. All on Bear's Mac: Apple M4 Pro (Apple9), macOS 26.5.1, Godot 4.7.2 stable (official), Forward+ on Metal 4.0, 2026-10-13. Every Godot run goes through the series' Shader Lab (`../../../_godot-shaders-series/lab/check_shader.sh`, a real windowed Godot) or a scratch GDScript project.
**Why.** So any figure on screen can be re-run, and so a reviewer can see what was measured and what was only read from the docs. A film about math functions can be checked far more thoroughly than one about taste, so it was.
**Found.** Eleven scripts (nine Python, two GDScript) and about 160 Lab runs. Everything the film says about a function matched the docs and the render. The strongest result: the curve the film draws for each function is **identical** to the picture Godot renders (21 curves of 640 pixels, largest difference 0 levels; 10 round pictures of 129,600 pixels, largest difference 1 level). The one new number, `smoothstep(0, 10, 1)`, reads 0.02797 (0.028), not the straight line's 0.1. Two behaviours the docs call "undefined" were observed on this Mac and are not relied on. One failed start (a setup error) is kept below.

Re-run any check from this folder: `python3 <script>.py` (each writes its own outputs; the Lab serializes runs, so they can take a minute or two). The GDScript checks run in a scratch folder: copy the script (and `project.godot`) into an empty folder and run `godot --headless --path <folder> --script res://verify_mod.gd` (the environment check needs a window, so no `--headless`).

## Failed and inconclusive runs (kept)

- **First start of `verify_mod.gd`: failed, not a measurement.** The script had not reached the scratch project (a chained `cp` step failed earlier in the same command line), so Godot printed "File not found" for `res://verify_mod.gd`. Its terminal output was not saved at the time; `run-0-verify-mod-FAILED-script-not-copied.log` reproduces the same command in a folder without the script and shows the same error. Fixed by copying the script; `run-1-verify-mod.log` is the successful run. (A `project.godot` turned out not to be needed for a `--script` run; the file in this folder is only there so the scratch checks have a project name and window size.)
- **Resolution limit, not a failure.** A pixel is a whole number of 255ths, so a direct read of 0.028 would be 0.0275 and could not separate it from nearby values. The check shader scales the output (by 15) before it reaches the frame buffer and the script divides it back: 0.02797. Every "scaled" or "encoded" row in `function-tables.md` and `extra-checks.md` states its scale and offset.
- **Nothing was inconclusive.** (The pilot's first `TIME` attempt was; this film has no timing claim.)

## Side findings for the shared files

- The Godot docs say `fragment()` "runs for every pixel covered by the mesh" and "once or more for each pixel it has to draw". `GLOSSARY.md` says "once for each pixel the shape covers", which is exact for one flat shape and loose when shapes overlap.
- The docs use "built-in" in two senses: values the engine hands in (`UV`, `TIME`), as in the GLOSSARY, and "built-in shader functions" (`step`, `mix`, ...). This film says "functions" for the second and keeps "built-in" for the first.
