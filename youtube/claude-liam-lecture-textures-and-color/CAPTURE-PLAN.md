# Capture plan: Textures and Color

**What this is.** Every Godot render, editor frame, screenshot and still the build session must record for this film, with the exact shader file, target, textures, values over time, duration, renderer and the result already verified. Nothing for the film is recorded yet except the editor frames (section E, recorded by script on 2026-10-13); the numbers below come from planning runs in `evidence/planning-checks/`.
**Why.** Films show only what was really done and recorded. This is the list of things to really do, written so a medium-effort session can do them without further judgment. Color is the film's subject, so every number a probe reads is listed with the renderer that produced it.
**Found.** 26 Godot captures (C01 to C26: 16 plain Lab, harness or scene runs and 10 composites of two, three or four renders), 3 editor captures (E1 to E3: all DONE by script, no click needed; B40 now uses the Project Settings frames), 1 docs screenshot (D1) and 2 stills for one Manim beat (S1, S2). All 28 shaders compile and run in the Shader Lab; every probe value below was read in a real Godot 4.7.2 window. The Lab alone cannot make this film's tiny F table, four-patch picture, burn ramp, grey ramp or NoiseTexture2D, so a short list of harness additions is given (section H) with a reference implementation that is already verified.

## Conventions for every capture

- 30 fps; render at 3840 × 2160 with the SubViewport native-size route (`../_godot-shaders-series/COMPONENT-SPECS.md`, Capture harness); logical canvas 1280 × 720, or 720 × 720 where a square table is shown ("square" below). The Lab stage color `#D9D5CA`. **Forward+ unless a row says otherwise.** Offline fixed tick rate, so nothing here says anything about real-time frame rate. Every scripted sweep or switch is labelled "scripted" in the film (`videoLabel`).
- **Times are fractions of the beat's measured audio** (convert with `--length SECONDS`): the length of each clip is the beat's audio, not a number written here. A "switch-on" is `--material-at` at the stated fraction; a "sweep" is `--animate name:t0:v0,t1:v1` with fractions; a "reveal" of a panel is an ffmpeg overlay that starts at the stated fraction.
- Output to `runtime/remotion/public/godot-textures-and-color/` with the names the lanes use.
- Compare every capture with its "verified result" column. If a probe disagrees, stop and report; do not edit the shader.
- A pixel value is only quoted with its renderer. The 8-bit captures carry plus or minus one step (0.004); with HDR 2D the value is the linear value converted to what the screen shows (the reference harness does this).
- Panels side by side in the **same renderer** may be one scene (`--scene`, as in the Lines film's `two_panels.gd`) or two renders joined by ffmpeg `hstack`; panels in **different renderers** (C22, C25) are always separate renders joined by ffmpeg.

## E. Editor frames (Godot's own editor, recorded by script on 2026-10-13: DONE)

Method: the editor driver (`../_godot-shaders-series/editor-capture/README.md`, sections 5, 7 and 11). An `EditorPlugin` runs a JSON state script inside the real Godot 4.7.2 editor, on a scratch project, while Movie Maker records the editor window; each named state is one PNG at 1920x1080 and at the native 3456x1944. No human click and no scratch work for this film: the build session copies the frames into `runtime/remotion/public/godot-textures-and-color/` under the names the lanes use. Popups and dialogs are recorded because the driver's settings turn Single Window Mode on; Movie Maker records no mouse pointer, so every clip is labelled "scripted editor session" in its `videoLabel`. Re-record only if a state is missing (`README.md` section 7; one run takes 17 to 56 seconds and holds the shared Lab lock). `P` below is `../_godot-shaders-series/editor-capture/png/1920x1080/` (native twins in `png/3456x1944/`; each frame also has a `.dock.png` crop of the right dock).

## H. Harness additions this film needs

The shared harness (`../_godot-shaders-series/COMPONENT-SPECS.md`: `--animate`, `--steps`, `--scene`, `--call-at`, `--time-origin`, `--set-at`, `--material-at`, `--keys`, `--renderer`, `--length`) covers the sweeps, switches and scenes. This film also needs the following, all implemented and verified in `evidence/planning-checks/runner_plus.gd` (a copy of the Lab's `runner.gd` with these extras, for still frames; port them into `capture.gd`):

1. **Texture kinds** for `--tex name=kind` beyond the Lab's `gradient`, `checker`, `noise`, `sprite`, `white`, `black`: `tiny_f` (6 × 6 texels, a cream letter F on teal with a one-texel teal margin: row by row `. . . . . .` / `. C C C C .` / `. C . . . .` / `. C C C . .` / `. C . . . .` / `. . . . . .`), `swatches` (128 × 128, four 64-pixel patches: rose `#E6598C`, leaf `#66A659` over sky `#6680D9`, sand `#E0B04A`), `ramp_grey` (256 × 256, value = x / 255 in red, green and blue), `burn_ramp_tex` (a GradientTexture1D, 256 wide, stops `#8A2A12`, `#F08A2C`, `#F7D46B` at 0, 0.5, 1) and `noise2d` (a NoiseTexture2D, FastNoiseLite seed 7, frequency 0.02, 256 × 256; wait until its image exists, it is generated on a thread). The Lab's `noise` kind is pixel-identical to `noise2d` (run-5), so either may be used for the noise; the F, the swatches, the grey ramp and the burn ramp have no Lab equivalent.
2. **Node options**: `--rect-color #RRGGBB` (the ColorRect's own color), `--modulate #RRGGBB` (a Sprite2D's modulate), `--size WxH` (a square window), `--hdr2d` (`Viewport.use_hdr_2d = true`; the frames, which the viewport returns in linear light, are converted with `linear_to_srgb` to what the screen shows).
3. **Composites**: `hstack`, `vstack`, `xstack` of two or four renders with a timed reveal (an ffmpeg overlay enabled from a fraction of the clip); or one scene with two panels in the same renderer.
4. **Scene scripts** (`--scene`): the three-patch scene (`verify-patches.gd`), a two-patch variant for C24 (set `tint` on each patch from code), the tween scene for C21 (`verify-tween-progress.gd` shows the calls and the failure mode).

## Not captured on purpose

- **Real-time frame rate**: nothing here says anything about it (the renders are offline at a fixed tick rate).
- **Lit 3D surfaces**: only unshaded quads were tested, so the film says "in this test" and quotes no lit result.
- **Other renderers' hardware**: Compatibility ran as OpenGL 4.1 on Metal on an Apple M4 Pro; no other GPU or platform was tested. Mobile is measured (it matches Forward+ in every cell) and appears in the tables, not in the pictures.
- **The editor clicks themselves**: E1 to E3 are states recorded by a driver script, not a screen recording of a person clicking; no pointer is visible and the clips say "scripted editor session".
