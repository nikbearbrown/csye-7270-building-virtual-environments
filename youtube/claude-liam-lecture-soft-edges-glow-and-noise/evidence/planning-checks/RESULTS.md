# Planning checks: results

**What this is.** The runs behind the numbers in `FACTCHECK.md`, in the order they were done, with the command, the result and what it means. All on Bear's Mac: Apple M4 Pro, Godot 4.7.2 stable (official), Forward+ unless stated, 2026-10-13.
**Why.** So any figure on screen can be re-run. Failed and inconclusive runs are kept and labelled (`run-0-first-runs-transcribed.txt`).
**Found.** One Lab batch of 42 renders, one glow matrix of 25 runs, five GDScript checks, 15 shader files that all compile. The biggest finding came from a run that first looked like a failure: the environment's glow does nothing in 2D until its background mode is Canvas. Every formula-driven picture matches its formula on all 65,536 pixels to within 0.008 (the 8-bit limit).

Re-run everything (each script holds the shared Shader Lab lock, so no Godot window overlaps another film's):

```
./run-lab-checks.sh      # 42 Lab renders -> lab-results.jsonl, png/*.png ; then: python3 -I analyze_lab.py -> lab-analysis.txt
./run-glow-checks.sh     # 25 scratch-project runs (HDR 2D, environment, stage) -> glow-results.jsonl ; python3 -I summarize_glow.py > glow-summary.txt
./run-script-checks.sh   # noise_check.gd, extra_checks.gd, toggle_check.gd, finale_check.gd -> run-noise.log, run-extra.log, run-toggle.log, run-finale.log
```

Never `pkill -f run-lab-checks.sh` (another film's batch has the same name); stop a run by its PID. A Godot window that another window fully covers is not drawn, and the shader clock then stands still: the time checks therefore step the clock themselves (see Y and `run-0-first-runs-transcribed.txt`, item 8).

**Side finding for the series.** `hint_range` and `source_color` behave as the GLOSSARY says (a hint shapes the editor, does not clamp), and the HDR 2D finding sharpens the color film's renderer story: with HDR 2D on, a `canvas_item` color uniform needs `source_color` or it comes out washed out in Forward+ (it does not in Compatibility).
