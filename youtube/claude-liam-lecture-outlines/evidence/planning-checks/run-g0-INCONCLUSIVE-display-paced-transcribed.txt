INCONCLUSIVE, kept. First attempts at the cost question (verify_g_cost.gd, early versions), 2026-10-13, Apple M4 Pro, Godot 4.7.2, Forward+, vsync off.
Read from the terminal, not saved to a log at the time, so transcribed here. Three rounds each, median ms per frame by round.

Attempt 1: ONE 4096 x 4096 render target per frame. Every variant read 8.3 ms: the frame loop was paced at the display's 120 Hz (8.33 ms), so the shader cost was hidden.
   plain sprite 8.33 8.31 8.31 | 5 reads 8.28 8.35 8.33 | 9 reads 8.34 8.31 8.35 | 10 reads (08-loop) 8.32 8.35 8.34 | ring 8.33 8.34 8.33
   25-read loop, runtime bounds 8.32 8.33 8.37 | 49 reads 8.30 8.33 8.32 | 81 reads 8.34 8.30 8.32 | guard at thickness 0 8.35 8.33 8.33
   The engine's own GPU timer (viewport_get_measured_render_time_gpu) returned 0.0 in all 4,050 samples: unavailable on this setup.

Attempt 2: ONE 8192 x 8192 render target per frame. Variants up to 25 reads still read 8.2 to 8.4 ms (hidden); 49 reads 10.4 ms; 81 reads 16.2 ms.
   So the method works only once the graphics card needs MORE than one display frame; the final run uses six 8192 x 8192 targets per frame (403 million pixels),
   which puts every variant above the floor except the cheapest: run-g-verify_g_cost.log and cost-summary.txt are the result the film uses.
