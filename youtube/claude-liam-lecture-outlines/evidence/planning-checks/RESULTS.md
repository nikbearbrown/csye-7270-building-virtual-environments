# Planning checks: results

**What this is.** The runs behind every number and every on-screen claim in `FACTCHECK.md`, in the order they were done, with what each script does, which log or summary holds the result, and what it means. All on Bear's Mac (Apple M4 Pro, Godot 4.7.2 stable official, Forward+ unless stated), 2026-10-13.
**Why.** So any figure in the film can be re-run (`./run_all.sh`, about eight minutes when nothing else is using the Lab) and so the failed and inconclusive runs are visible, not hidden.
**Found.** Fifteen GDScript checks, one Lab batch (47 renders), 27 capture specs (26 clips, 1 still) played and measured at the film's own 1280 by 720 geometry (all 27 also compared across the two render routes), and 13 Godot docs pages and one reference chapter read (the raw text was searched, not only summarised). Three runs did not answer first time and two stress-test runs stopped drawing: all five are kept and labelled below. A final audit of the logs found three more that had silently measured the wrong thing (a renamed shader file); those were fixed and re-run, and the audit is described below. Findings that surprised me are marked **new**.

Re-run everything: `./run_all.sh`. One scene: `./run_scene.sh C13-thickness-steps --times 7.1`. The Lab batch alone: `python3 run_lab_checks.py` then `python3 analyze_lab.py`. Scratch scripts run in a throw-away project that `run_scratch_checks.sh` creates in the temp folder (never in the film folder); they find the shaders through the environment variable `OUTLINE_FILM_DIR` (the script sets it). **Leave the Godot window uncovered while `./run_scratch_checks.sh g` runs** (a covered window stops drawing: see the invalid run below).

## Runs that did not answer first time (kept)

- `run-j0-FAILED-first-attempt-test-harness-bug-transcribed.txt`: the first version of `verify_j_select.gd` built the select node wrongly (a test-harness bug, "Can't add child 'Sprite'"); the script was fixed and re-run; the shared-material results in that log were already valid.
- `run-d0-mascot-v1-INCONCLUSIVE-transcribed.txt`: the first antenna sprite had a neck too short to come apart and the printed slice crossed the ball.
- `run-g0-INCONCLUSIVE-display-paced-transcribed.txt`: the first wall-clock timings were paced by the display (8.33 ms for every variant).
- `run-g1-INVALID-covered-window-transcribed.txt` and `run-g-repeat-4-INVALID-window-stopped-drawing.log`: two repeats of the stress test in which, from round 2 on, every frame read the idle time (6.9 ms), whatever the shader. The first happened while other windows covered the Godot window; the second happened even with the window kept on top, so the cause is the system, not only a cover. Round 1 of each agreed with the valid runs to within about 1 ms. `verify_g_cost.gd` keeps its window on top and `analyze_cost.py` lists such a run as INVALID and leaves it out; the film's numbers are the median of the valid runs.
- **Three logs that looked fine and were not**, found by scanning every log for `ERROR` lines after the main runs: `run-m-verify_m_modulate.log` (the third sprite's shader file had been renamed, so it drew with no shader and the summary said the line was not there), `run-i-verify_i_sizes.log` (the sheet-safe shader, same cause) and `run-j-verify_j_select.log` (the instance-uniform shader, same cause). The scripts were corrected to the final file names (`14-modulate`, `12-sheet-safe`, `13-instance`), all re-run, and the numbers in findings 11, 15 and 16 are from the re-runs. The remaining `ERROR` lines in `run-j` and `run-a` are Godot's exit-time leak reports for nodes freed inside a script run, not failed checks.
- Small ones, not worth a log: a GDScript type-inference parse error in the first padding script; a first bigger-copy measurement that used the wrong colour class (analysis bug, fixed); the scene player failing to parse once (a type-inference error) after which the runner hung until I added a load check; an early analysis whose default search radius was too small at 3x.
