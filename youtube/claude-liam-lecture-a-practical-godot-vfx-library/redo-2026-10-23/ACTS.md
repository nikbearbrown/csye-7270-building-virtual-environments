# Source coverage and acts

Six acts: layered explosion with five soloable jobs and tail fault; alpha/additive smoke/fire and a procedural four-cell flipbook; unwanted shared surface edits and independent surface repair retaining texture identity; contact-driven rain/sub-emitter with capacity/cleanup; ground dust and world-space trails in 2D; delayed charge/release and optional light; reusable scenes, repeated lifecycle checks, and actual renderer pricing. Native visual verification is still required before accepting any effect-specific claim.

- B01 · Build An Explosion · Start with the empty three-dimensional stage, using Forward Plus on Metal for the later contact-driven sub-emitter. We will build an explosion from separate visual jobs: a flash, a hot expansion, sparks, a smoke tail, and a ring. The editor preview repeats each event so we can inspect its complete life.
- B02 · Build An Explosion · Add one short-lived flash particle with a large soft quad. Its additive material makes a bright onset. This layer lasts less than a fifth of a second; it should announce the event without pretending to describe the whole explosion.
- B03 · Build An Explosion · Add the hot expansion. Twelve small quads move outward while a growth curve enlarges them. Solo this layer. Its short, changing silhouette carries the peak; the flash only made that peak easier to notice.
- B04 · Build An Explosion · Add mesh sparks with faster launch and downward gravity. These particles give the eye a direction to follow after the flash. A few readable trajectories are more useful here than a dense cloud of identical points.
- B05 · Build An Explosion · Build the slower smoke tail with alpha-blended quads. It rises, expands, and fades over more than two seconds. Soloing it makes its timing clear: smoke explains the aftermath, not the impact itself.
- B06 · Build An Explosion · Add an expanding ring, then show every layer together. The ring is another soft textured particle, with a different silhouette. Its scale curve creates expansion; its lifetime and alpha ramp end the image.
- B07 · Build An Explosion · Remove the smoke tail for one comparison, then restore it. Next reduce the spark count from thirty-two to sixteen. Keep the version whose onset, peak, and decay still read. More particles are a cost, not an explanation.
- B08 · Build Smoke And Fire · Start a campfire scene with a continuous smoke plume. Continuous means new particles are born throughout the cycle. The plume has a slow upward motion and a broadening alpha silhouette, so it reads as smoke before we add a flame.
- B09 · Build Smoke And Fire · Add a faster, shorter flame layer, then a few small embers. The alpha smoke darkens and softens the scene; additive flame adds light to the image. Those different visual jobs justify different material choices.
- B10 · Build Smoke And Fire · Change the environment from dark to light, then restore it. Inspect both flame and smoke against each background. Additive blending can disappear into a bright scene, while alpha smoke depends on contrast and overlap.
- B11 · Build Smoke And Fire · Here is an intentionally crowded plume. Increase the smoke count and size, then reduce both. Overlapping transparent cards add drawing work and may introduce ordering artifacts. Keep the shape, but remove layers that do not improve its message.
- B12 · Build Smoke And Fire · Assign this original four-cell smoke texture. The grid is visible in the actual material preview. Set four horizontal frames, one vertical frame, and a single animation cycle. The process animation speed advances through that grid over each particle’s life.
- B13 · Build Smoke And Fire · Duplicate the smoke and change its shared surface tint. Both copies change. Make only the mesh and surface material independent, then restore one tint. The texture remains shared because a color edit does not require another copy of its pixels.
- B14 · Build Smoke And Fire · Restore a neutral smoke tint and save the campfire. Keep the individual smoke scene too. The flipbook is an optional appearance layer; the slow rise, growth, and fade still need to work when we return to a single soft texture.
- B15 · Build Rain And Contact · Build rain over an area rather than at one point. A box-shaped emission region covers the stage. Long narrow meshes move downward quickly, so the first visible drops already communicate falling rain.
- B16 · Build Rain And Contact · Add a particle collision box at the ground and a separate splash pool. A floor mesh alone does not create particle contact. The splash emitter begins inactive and uses rigid contact to emerge above the surface. It receives individual particle births from the parent effect.
- B17 · Build Rain And Contact · Connect Drops to the Splash child as its sub-emitter. Use contact-driven emission and one splash particle per contact. The visible test must show births at impact positions; a decorative ground emitter would be a different mechanism.
- B18 · Build Rain And Contact · Disable the contact mechanism, then restore it. Watch the ground rather than the top of the frame. This comparison separates falling streaks from contact splashes and checks that the child pool is doing the job we claimed.
- B19 · Build Rain And Contact · Orbit across the rain volume and inspect its visibility bounds. The emitter must cover the playable view, and the bounds must cover the moving particles. A large box does not repair missing coverage or create a collision surface.
- B20 · Build Rain And Contact · Keep the splash capacity explicit: sixty-four slots and a short lifetime. Stop new rain, wait for the existing drops and splashes to finish, then replay. Save the effect with the renderer and contact-test evidence that actually passed.
- B21 · Build Dust And Trails · Move to the two-dimensional ground test. Add a one-shot dust emitter at the contact line. Upward launch and downward gravity make a short puff that returns toward the ground instead of floating like smoke.
- B22 · Build Dust And Trails · Reduce the spread, then restore a wider ground puff. Keep the contact line fixed while comparing the silhouettes. The effect should tell us where the contact happened; moving the emitter to hide a weak shape would change the question.
- B23 · Build Dust And Trails · Duplicate the emitter as a trail and make its process resource unique. Turn one-shot off and spread births through time. Its lower speed and shorter lifetime make a persistent movement cue rather than another impact.
- B24 · Build Dust And Trails · Move the emitter with local coordinates off. The trail records positions left behind the source. Turn local coordinates on for comparison, then restore world space. That single choice changes a trail into an attached cloud.
- B25 · Build Dust And Trails · Turn the trail condition off and let existing dust finish. Turn it on again while the source moves. A continuous effect has both an on-state and an off-state; the off-state is part of the design, not cleanup to consider later.
- B26 · Build Dust And Trails · Save separate dust and trail scenes with their independent process resources. Their texture can remain shared. The ground puff communicates a contact event, while the trail communicates movement over time.
- B27 · Coordinate Magic And Timing · Return to the three-dimensional stage and build a magic effect. Its controller will coordinate a charge, a release, and an aftermath. Timing makes the action readable before we increase detail or particle count.
- B28 · Coordinate Magic And Timing · Add a compact blue charge cloud that emits for one and a half seconds. Its small volume announces preparation. The controller owns that time window, so the particle scene does not have to decide when a gameplay action is allowed.
- B29 · Coordinate Magic And Timing · Add a fast release burst with a delayed start, followed by a slower ring. These are familiar layers with different timing and color. The release begins after the charge; adding everything at time zero would erase that distinction.
- B30 · Coordinate Magic And Timing · Add a brief light pulse at release, then compare with the light disabled. The pulse affects nearby surfaces; the bright particle material affects the image. Keep both only if their combined timing helps the action read.
- B31 · Coordinate Magic And Timing · Open the actual controller. It tracks elapsed time, starts each layer at its delay, and stops continuous births at their stated end. It also computes when the last particle can finish before freeing a spawned instance.
- B32 · Coordinate Magic And Timing · Replay the complete charge and release from a second angle. The sequence should remain readable at game scale without relying on the editor selection outline. Save it as a reusable scene with the timing controls intact.
- B33 · Package And Price · The library now has explosion, smoke, campfire, rain, dust, trail, and magic resources. Each scene has a visual job and explicit replay or emission behavior. Reuse the scene contract; do not copy unexplained parameter piles into the game.
- B34 · Package And Price · Open the spawn path in the stage script. Space loads a saved scene, marks it for bounded disposal, and calls play. The scene’s tree-exited signal updates the cleanup count, so repeated use has observable state.
- B35 · Package And Price · Run the stage and trigger the saved explosion three times. Watch the active-instance counter rise and return to zero after the smoke tail finishes. This checks the whole layered scene, not only the first bright frame.
- B36 · Package And Price · Compare the same stage with layers off and on using the recorded measurement fixture. Its report names the renderer, resolution, warm-up, sample count, and instrument. A smooth recording alone tells us none of those costs.
- B37 · Package And Price · Read the actual cost report beside those conditions. Zero or unavailable GPU timing is not free rendering. Look for the difference from the empty stage, and preserve both the useful shape and a budget for the rest of the frame.
- B38 · Package And Price · Return to the saved library and its source. Keep the procedural texture generator, tests, renderer notes, and complete-effect recordings with the scenes. A reusable effect is something the next person can trigger, inspect, change, and finish safely.
