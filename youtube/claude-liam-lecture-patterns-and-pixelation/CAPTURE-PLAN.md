# Capture plan: Patterns and Pixelation

**What this is.** Every Godot render and screenshot the build session must record for this film, with the exact shader file, target, values over time, duration, renderer and the result already verified. Nothing is recorded yet; the numbers below come from planning runs in `evidence/planning-checks/`.
**Why.** Films show only what was really done and recorded. This is the list of things to really do, written so a medium-effort session can do them without further judgment.
**Found.** 22 Godot renders (18 from the Shader Lab with the shared harness, 4 small scene scripts), 1 docs screenshot, no editor frames and no interactive editor actions. Every shader compiles and every number below was read from a real Godot 4.7.2 window on Forward+ (and checked identical on Compatibility where noted). The motion in the sweeps and switches is scripted and has been verified at its end points with still renders; the videos themselves are not yet recorded.

Conventions for all captures: 30 fps; render at 3840 × 2160 using the Signal Garden SubViewport native-size route (see `../_godot-shaders-series/COMPONENT-SPECS.md`); the Lab stage color `#D9D5CA`; **Forward+** unless stated; **nearest texture filter** (the Lab's sprite scene uses it; the videoLabel says so); offline fixed tick rate, so nothing here says anything about real-time frame rate; every scripted change is labelled "scripted" in the `videoLabel`. Output to `runtime/remotion/public/patterns-and-pixelation/` (video or PNG as named in the lane). "Fit scale" means the Lab's default sprite scale (the 128 px texture drawn at 288 px, a square on the stage); "scale 1.0" means one picture pixel is one screen pixel (used only for measurements, not for the film). Timings marked "from the audio" are set from the measured narration so a switch lands on its word (the lane's `show` cue says which); the estimates below use 0.34 s per word.
