# Planning checks: results

**What this is.** The runs behind the numbers in `FACTCHECK.md`, in the order they were done, with the script, the log and what each found. All on Bear's Mac: Apple M4 Pro, Godot 4.7.2 stable (official), 2026-10-13, every check in both Forward+ and Compatibility (the `run-NN` logs come in pairs).
**Why.** So any figure on screen can be re-run, and so a reader can see which findings changed the film. Failed and inconclusive runs are kept and labelled in `run-00-first-attempts-transcribed.txt`.
**Found.** Ten check scripts, 23 capture scenes that run, one Lab batch, a palette check and a read of the real editor's labels. One result overturned the plan (a canvas layer takes its own copy of the screen, so the stale-copy trap the plan opened Act IV with does not exist across layers); one corrected the obvious game-side line (position over screen size is wrong once a camera moves); four behaviours differ between the Forward+ and Compatibility renderers (the film claims none of them for both, and says aloud, once, which renderer obeys `filter_nearest`); and one concerns the recording, not the engine: a mip-level blur is less than half as strong through the 3840 x 2160 capture route, so that one capture (C13) is recorded natively at 1920 x 1080.

**Re-run:** `./run-checks.sh verify1 [forward_plus|gl_compatibility]` (any `verifyN`, `smoke_compile`, `scene_frames`), `./run-checks.sh scene <scene> <seconds> <u list> [renderer] [--route sub4k|native1080]`, `./run-checks.sh capture <scene> <seconds> [renderer] [--width W --height H --frames N] [--native]`, `./run-lab-checks.sh`, `./editor-labels/run-editor-labels.sh`, `python3 palette-check.py`, `python3 capture_all.py --dry-run`. `run-checks.sh` builds a scratch Godot project from this folder and `../../lab-shaders/`, serialises with the Shader Lab's lock, and writes `run-logs/`. `rts_lib.gd` is the shared library (the meadow, helpers); every scene extends `rts_scene.gd`.

## Renderer differences found (nothing below is claimed for both)

| Behaviour | Forward+ | Compatibility |
|---|---|---|
| `repeat_enable` on the screen texture, read past the edge | wraps to the far side | clamps to the edge pixel |
| `textureLod(..., 4.0)` with no filter hint | unblurred (same as level 0) | blurred |
| `filter_nearest` against `filter_linear`, magnified 50 times (verify4 L7b, verify9) | nearest gives a hard step, linear a ramp (the default is linear) | all three read alike: the hint is not obeyed for the screen texture. **B36 says so aloud** |
| blur at level 2 and 4 (largest neighbour step) | 0.012, 0.008 | 0.024, 0.012 |
| everything else measured (the copy, layers, overlap, BackBufferCopy, invert, gray, spotlight, shift, ripples, tint, mouse filter) | same result | same result (every comparison inside one renderer came out the same; a few meadow spots differ between the renderers by up to 12 levels of 255, so no figure on screen quotes a raw meadow colour) |
