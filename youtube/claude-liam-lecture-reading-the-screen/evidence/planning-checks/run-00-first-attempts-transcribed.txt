These are the first attempts that did not give the answer, transcribed from the terminal on 2026-10-13 (Apple M4 Pro, Godot 4.7.2, Forward+ unless stated).
They were not saved as logs at the time. Each is labelled: WRONG EXPECTATION (the engine disagreed with the plan, and the plan changed), INCONCLUSIVE (the probe could not
answer), BAD REFERENCE (my own measurement was wrong, fixed and re-run) or TOOLING (a script or shell slip). The saved logs run-01 to run-21 are the corrected runs.

== 1. WRONG EXPECTATION: a reader on a higher layer would read a stale copy (13:57, verify2 M4 and M5, first run)
Plan: the docs say subsequent nodes that use hint_screen_texture "will not have the screen copied for them", so a full-screen filter on layer 1 should reuse the copy
a pool on layer 0 made, and so ERASE the pool and the player (they are drawn after the pool's copy). The film's Act IV was going to open on that bug.
Measured (the miniature lens, second reader on layer 1, nothing between): the lens showed the first reader's output and the block drawn after it.
  RESULT {"id":"M4-second-reader-on-a-higher-layer-still-stale","lens":{"A_window_inverted_world":[0.451,0.2588,0.549],"X_red":[0.8784,0.251,0.1843],"Y_blue":[0.1843,0.4353,0.8784], ...}}
  RESULT {"id":"M5-full-screen-identity-reader-after-another-reader", "X_before":[0.8784,0.251,0.1843],"X_after":[0.8784,0.251,0.1843], "A_before":[0.451,0.2588,0.549],"A_after":[0.451,0.2588,0.549], "Y_before":[0.1843,0.4353,0.8784],"Y_after":[0.1843,0.4353,0.8784]}
The id strings say "still-stale" and "erased" because that was the expectation; the numbers say the copy was fresh. A follow-up (verify2b P1 to P5) found the real rule:
two readers in one canvas layer share one copy; a new CanvasLayer takes its own. The film's Act IV was rebuilt around that (B30, B32 to B34).

== 5. TOOLING: the Shader Lab batch (14:23, run-lab-checks.sh, first run)

backslash-n inside a string into a real newline. Fixed with an argument array and printf; re-run after the final shader edits (lab-results.jsonl).

== 7. WRONG PLACE: the editor's Full Rect (14:50, editor-labels, first run)
The plugin searched every PopupMenu in the editor for "Full Rect" and "Anchor" and found nothing. The Inspector's Anchors Preset is an OptionButton inside the property widget, not a

(The "NOTE popups containing ..." lines in the final log are still empty for that reason; the WIDGET lines hold the answer.)

== 8. NOT A FAILURE, A FINDING: set_anchors_preset alone (13:57, verify2 M7, first run)
  RESULT {"colorrect_full_rect_size":[0.0,0.0],"colorrect_without_layout_size":[0.0,0.0],"full_rect_position":[0.0,0.0],"id":"M7-full-rect","viewport_size":[1280,720]}
