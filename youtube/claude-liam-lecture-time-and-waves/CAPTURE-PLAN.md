# Capture plan: Time and Waves

**What this is.** Every Godot render and screenshot the build session must record for this film: the shader or scene script, the target, the values over time, the scripted input, the length, and the result already verified. Nothing is recorded yet; every number below comes from a planning run in `evidence/planning-checks/` (640 by 360, Forward+ unless stated).
**Why.** Films show only what was really done and recorded. This is the list of things to really do, written so a medium-effort session can do them without further judgment, and with a way to tell, for each one, whether the recording is right.
**Found.** 18 Godot captures (8 Lab renders of one shader, 10 from 8 scene scripts that already run under Movie Maker at 30 fps), 1 docs screenshot, 0 editor frames, 0 editor actions. All 13 shaders compile in both renderers (`lab-compile.txt`). The scene scripts are the build's starting point: they load the shaders from `lab-shaders/`, are driven by a frame counter, and were decoded frame by frame (`scene-project/logs/`).

## Conventions for every capture

- 30 fps; 3840 × 2160 through the Signal Garden SubViewport native-size route (see `../_godot-shaders-series/COMPONENT-SPECS.md`); stage color `#D9D5CA`; Forward+ (state it in every `videoLabel`); never claim real-time frame rate: a capture is offline at a fixed tick rate.
- Output to `runtime/remotion/public/godot-shaders/time-and-waves/` with the file names the lanes use.
- **The window must keep being drawn.** `TIME` only advances on drawn frames: a hidden, minimized or covered Godot window stops drawing and `TIME` freezes (measured: `gd/logs/run-0b` and `run-1a`; FACTCHECK last row). Run every capture and every check with `--always-on-top` and leave the machine alone while it runs.
- **`TIME` in a capture.** Under Movie Maker at 30 fps, `TIME` advances exactly 1/30 s per written frame from about the eighth frame on (the first few frames jitter by up to 8 ms), so the frame at index n shows `TIME` of about (n + 1) / 30 s. `Engine.time_scale` scales that step per frame (1/60 s at 0.5); `paused` does not (`scene-project/logs/run-6-mm-time-per-frame.log`, `decode-scenes-act1.txt`). Scenes count FRAMES for their scripted events, never `delta`, so a time scale cannot move the script.
- Events are given in capture seconds. The build may trim the head of a capture (never retime playback) so an event lands on the spoken word named in the lane's `show` cues.
- A scripted input is logged and labelled "scripted input" on screen (C40, B03's time scale and pause are scripted too and labelled in `videoLabel`).
- Pulses that are pale at the 50 % or 85 % mark can fail Gate V's separation test. Fix it with the head trim or, if the harness has it, `--time-origin` (offset the shader clock), never by editing a shader: once the beat length L is known, choose the trim d (0 to 1 s) so that sin(TAU × (0.5 L + d)) and sin(TAU × (0.85 L + d)) both lie between -0.5 and 0.5 for a one-hertz pulse.
