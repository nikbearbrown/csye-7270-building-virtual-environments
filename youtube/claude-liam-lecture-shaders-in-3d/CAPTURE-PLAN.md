# Capture plan: Shaders in 3D

**What this is.** Every Godot render, editor frame and screenshot the build session must record or copy for this film, with the exact shader file, scene, values over time (as fractions of the clip), renderer, what must be visible at the 50 % and 85 % marks, and the result already verified. Nothing for the film is recorded yet except the editor frames of B43 (recorded by script on 2026-10-13); the numbers come from planning runs in `evidence/planning-checks/`.
**Why.** Films show only what was really done and recorded. This is the list of things to really do, written so a medium-effort session can do them without further judgment. Where a picture could not be verified at layout time it says so.
**Found.** 19 Godot captures (7 Shader Lab renders or composites, 12 from six small scene scripts S1 to S6), 2 docs screenshots, and 1 editor capture (E1, beat B43: four frames of the editor's Project Settings, already recorded by script, to be copied; no editor action and no recording by hand). Every shader is a file in `lab-shaders/` that compiled in the Lab; every probe value below was read in a real Godot 4.7.2 window on an Apple M4 Pro. The scene scripts needed here are small; each has a verified reference script in `evidence/planning-checks/`. Two things changed after the first plan and are explained in place: the lamp beat has its own clip (C03a), and the pad's held stills are at activation 0.3, where its stripes can be seen (`evidence/planning-checks/stripe-contrast.txt`).

Conventions for all captures: 30 fps; render at 3840 × 2160 by the Signal Garden SubViewport native-size route (`../_godot-shaders-series/COMPONENT-SPECS.md`, "Capture harness"; every shader here works in the mesh's own `UV` or in plain colors and none reads window pixels, so no capture needs the 1920 × 1080 native route); stage color `#D9D5CA` (`RenderingServer.set_default_clear_color`); Forward+ unless a row says otherwise; offline fixed tick rate, so nothing here says anything about real-time frame rate; every scripted motion or call is logged and labelled "scripted" on screen (the lane's `videoLabel` already says so, without any number of seconds). Output to `brutalist.art/runtime/remotion/public/shaders-in-3d/` with the file names below (the lanes use them). **Each clip is as long as its beat's measured duration** (audio first, "Audio-first timing" below); the lengths in the "Design length" column are only the first estimates.

**Framings (checked).** The object spacing and orthographic camera sizes below were tried at 1280 × 720 in `evidence/planning-checks/verify13-framings.gd` (log `run-13-framings.log`, contact sheet `png/framing-sheet.png`); every object stays inside the frame, and the non-stage pixels fill: C03 and C03a x 0.34 to 0.65, y 0.22 to 0.78; C04 x 0.22 to 0.78; C05 x 0.17 to 0.83; C06 x 0.19 to 0.81; C02 x 0.10 to 0.90 at swings of -50°, 0° and +50°; C18 x 0.14 to 0.86; the face-on square of S5 (C07, C10, C11) x 0.25 to 0.75, y 0.05 to 0.95; C14 x 0.15 to 0.85 (size 3.2; at the first plan's 4.2 it filled only 0.23 to 0.77). The readout x positions in the lanes are these object centres as fractions of the frame width. The camera size is the way to fill the frame (Gate V); do not crop a capture past its window.

**Type-gate design (GATE T at 4K).** The pad's rust (0.40, 0.16, 0.09) and its dark stripes sit within 48 RGB of the ink color, so any frame where most of the pad is still rust can read as a text blob. Every capture below is therefore timed so the frames at the 50 % and 85 % marks are mid-tone (green or half-green); the rust frames come only at the start of a sweep. **Held stills of the pad (C13, C14) are at activation 0.3**, not 0.5: at 0.5 the dark and light stripes differ by only 3.5 on the CIE76 scale in Forward+ (a red-channel step of 13 levels), too little to see where the film asks the viewer to count them; at 0.3 they differ by 5.7 and the dark stripe is still 52 RGB from ink (Forward+; `stripe-contrast.txt`). If GATE T flags a held still, hold at 0.4 (difference 4.6, dark stripe farther from ink), then 0.5, and say so in `BUILD-LOG.md`; do not change the shader. The Compatibility renderer's dark stripe sits close to ink until about 0.5 (C15 and C16 are a sweep and a still that include or sit at 0.5, where it is 48 away): watch those frames.

**Interface assumed between a scene script and the harness** (the pilot's build writes `capture.gd`; if it defines this differently, change the scene scripts to match it, never the numbers in this plan): a scene script builds its nodes under the root it is given; it keeps each shader material it creates in a dictionary `materials` under a short name (S1 and S5: `pad`; S3: `lit`, `unshaded`, `empty`), so `--animate pad.activation:...` and `--set-at SECONDS:pad.activation=VALUE` address `materials["pad"]`; it has the methods that `--call-at SECONDS:method` names (`lamp_on` for C03a, `fire` for C10, `start_tween` for C11, `give_shaders` for C18); and any motion of its own (the swing, the turn, the lamp's yaw) is computed from the clock the harness hands it, never from real time.
