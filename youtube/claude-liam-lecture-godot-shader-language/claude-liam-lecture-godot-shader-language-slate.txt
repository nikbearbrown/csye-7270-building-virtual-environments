Go Do Shader Language. Learn how a shader file is built, what its types and vectors mean, and how to read any shader line by line, even one an AI wrote for you. Hello, this is Liam in ForBare. When you first read shader code, it is natural to assume each line works on one number at a time. It does not. Many values in a shader are bundles of numbers, and one operator works on the whole bundle at once. Five terms, a shader is a small program the graphics card runs to decide how something is drawn. A pixel is one dot of the picture. A type is the kind of value something holds. A function is a name block of code you can call. An argument is a value you hand it. Here is a real shader, 14 lines long. It makes a color breath between pale gray and teal. Go Do refuses a line that breaks the rules. It will not warn you when a legal line to something you did not mean, so you have to read it. A shader file has three zones read from the top down. The header says what kind of shader this is. The globals are values declared outside every function. The functions are where the work happens. The header starts with shader type and it must be the first line. Canvas item means 2D drawing an interface. Spatial means 3D. An optional second line render mode picks options such as how a pixel blends with the background. Global sit outside every function. A uniform is a value your game sets from outside. A const never changes. A varying hands of value from a shape's corners to its pixels. There each one above the code that uses it. Then come the functions. Go Do calls three of them for you. Vertex places the corners. Fragments sets the color of each pixel and light handles each light that touches a pixel. This film uses fragment. Any other function is one you write yourself. Inside a function every statement ends with a semicolon and braces group statements into a block. Forget one semicolon and Go Do refuses the whole shader. Here at points at the next line where it noticed. Spacing and line breaks are for people. Here is one shader that draws a soft gradient written three ways. Kneet, squeezed onto one line and spread over many. Go Do draws the same picture for all three. Comments are notes for people. Two slashes comment out the rest of a line. Slash star starts a block comment and star slash ends it. Go Do skips both so a commented outline does nothing. Go Do's language is close to GLSL, the shading language of open GL but not identical. Names must match exactly. Capitals included. A capital L makes level a different name. The other languages GL Frag color is unknown here. Go Do calls it color. Every value has a type. A float is a decimal number. An int is a whole number and a pool is true or false. A texture has a type 2 called sampler 2D. You declare a variable with its type first and its name. Go Do is strict about this. A 2 with no decimal point is an int and Go Do will not quietly turn it into a float. Put it in a float or add it to one and the shader will not compile. Write 2.0. Shaders are full of vectors, bundles of 2 to 4 numbers. Vect 2, Vect 3, Vect 4. A color is a Vect 4, red, green, blue and alpha, how solid it is. Reading a texture gives back a Vect 4 too. You build a vector by naming its type. Give Vect 3 one number and it fills all three parts. Give Vect 4 a Vect 3 in a number and it joins them. The pieces must add up to the size or Go Do refuses. Arithmetic works on every part at once. Multiply a Vect 3 by 2.0 and all three numbers double. Multiply two vectors and each part meets its partner. That is why shader code is so short. Here it is in use. UV is the address of each pixel of Vect 2. Join it with one half to make a Vect 3, scaled by 0.6 add 0.4. Red grows to the right, green grows downward. You can reach into a vector by name. rgb takes red, green and blue from a Vect 4. .xy takes the first two parts. Picking or reordering parts like this is called swizzling. Order is yours to choose. .br reverses the order and the gradients colors turn over. rgba xyz w and stpq name the same parts but never mix sets in one swizzle. Go Do refuses. The type on the left must match the type on the right. Color is a Vect 4. Handed a Vect 3 in Go Do refuses. Fix it by adding alpha, Vect 4 of C in 1.0. To read any lines say the type of each piece from the inside out. UV is a Vect 2. Join with one half of Vect 3. Times a float still a Vect 3. Plus a float still a Vect 3. Now your own functions. The first line of a function is its signature. It has three parts. The type at hands back its name and its arguments each with a type. Calling the function hands values into the arguments in order. The body runs. Then return hands one value back and it must of the type the signature promised. Break that promise and Go Do says so. Go Do reads from the top down. A function must be defined above the one that calls it. Call it first and the message says no matching function found. It does not say the order is wrong. A function you write cannot see most built-ins. A built-in is a value the engine hands to a function. UV and color are handed to fragment not to your function. Use UV inside yours and Go Do says unknown identifier. The fix is to pass what you need in as an argument. Here UV goes in as a dress and the same gradient appears. A few built-ins are global such as time and pie and any function can read those. Arguments come in three modes. In the default hands over a copy so changes stay inside the function. In out hands over the original so the color's variable changes. Out is for writing a result back. The functions Go Do gives you follow the same pattern and the documentation lists each signature. In it, Vec type means a float or a Vec 2, 3 or 4. Sign takes one of those and hands back the same type. A name can be reused if the argument types differ and Go Do picks by type. This call passes one and int and gets teal. This one passes 1.0 a float and gets sand. Same name, same digit, different function. And if needs a bool, a comparison like UV dot x less than one half gives true or false. If true, the first block runs otherwise the else block. Declare c above, a variable made inside braces ends at the closing brace. The ternary is a one line if, write the condition, a question mark, the value of true or colon, then the value of false. It gives back a value so it can sit inside a longer line, same picture one line. A for loop repeats a block. This one runs five times with the counter eye going from 0 to 4 and each pass draws one stripe. The counter is an int so convert it with float of eye before mixing it with decimals. Use for when you know the count and while when you do not, take care. On modern graphics cards an infinite loop can freeze your application. The editor included and Go Do cannot protect you from it. Compare floats against a range not with equals. Light UV dot x equal to exactly one half and nothing draws here. No pixel center lands on it. A small range draws a thin line. The documentation warns float math varies by hardware. Two performance notes from the documentation. Discard which throws a pixel away has a cost. Modern graphics cards handle and if well when every pixel takes the same path but too many branches can slow a shader down. This film did not measure either. Now read the file from the top.
