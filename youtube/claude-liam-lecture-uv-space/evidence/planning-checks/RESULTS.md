# Planning checks: results

**What this is.** The runs behind the numbers in `FACTCHECK.md`, with the command, the result and what it means. All on Bear's Mac: Apple M4 Pro, Godot 4.7.2 stable (official), Forward+ unless stated, 2026-10-13. The Godot 4.7 documentation pages quoted in the fact-check were fetched the same day (listed in `FACTCHECK.md`).
**Why.** So any figure on screen can be re-run. Failed and expected-failure runs are kept and labelled.
**Found.** One Lab batch (`run-lab-checks.sh`: every shader the film shows plus the evidence-only ones, 94 runs, one expected failure), pixel measurements of its PNGs (`measure.py`), and four scratch GDScript checks for what the Lab cannot do. Five results the sources do not give: `TEXTURE_PIXEL_SIZE` is one by one on a `ColorRect` and `SCREEN_PIXEL_SIZE` is the screen's, so only a uniform is right on every node; a node's `texture_repeat` applies to a shader's reads on a `TextureRect` although the docs say it does not; a flip swept through zero shows one stretched row; a picture scrolled with `TIME * 0.1` moves left at 0.1 pictures per second; and the lookup shader is pixel-identical to no shader at all.

Re-run the Lab batch: `./run-lab-checks.sh` (writes `lab-results.jsonl` and `png/`; `python3 summarize-lab.py` prints `lab-summary.txt`). Re-run the scratch checks: `./run-scratch-checks.sh` (copies the scripts into a scratch Godot project under `/private/tmp` and writes `run-1-aspect.log`, `run-2-repeat.log`, `run-3-scroll.log`, `run-4-identity.log`). In the Lab batch a "fill-window" run is a 256 x 256 window with the 128 px sprite at scale 2, so a probe position is a `UV` value; the other runs use the Lab's 640 x 360 window.
