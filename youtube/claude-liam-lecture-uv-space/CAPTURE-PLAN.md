# Capture plan: UV Space

**What this is.** Every Godot render and screenshot the build session must record for this film, with the exact shader file, target, values over time, duration, renderer, what must be visible at the 50 % and 85 % marks, and the result already verified. Nothing is recorded yet; the numbers below come from planning runs in `evidence/planning-checks/`.
**Why.** Films show only what was really done and recorded. This is the list of things to really do, written so a medium-effort session can do them without further judgment.
**Found.** 19 Godot renders, all through the Shader Lab route (no custom scenes, no scripted input, no editor frames), plus 1 docs screenshot. All shaders compile, and every probe value and pixel measurement below was read in a real Godot 4.7.2 window on Forward+ (the geometry was also run on Compatibility and is identical). The Shader Lab's options cover every setup; the capture harness needs only piecewise-linear uniform schedules (`--animate`), one step (`--set-at`), a material switch (three captures: C03, C07 and C13) and the existing `--tex`, `--sprite-tex` and `--size` options.

## Conventions for all captures

- **Timings are fractions of the beat's measured audio length `L`** (the seconds in the table are for the estimate, `0.34 s per word`). Render each capture for `L + 1 s` and hold the last frame. The build session scales every keyframe by the measured `L`.
- **Schedules** are written `name = value until a, then v0 to v1 over a-b, hold`: linear between the two times, held at both ends. Floats only. Uniforms not mentioned keep the shader's default. The next paragraph turns them into harness options.
- **How to pass them** (option syntax from `../_godot-shaders-series/COMPONENT-SPECS.md`): `seconds = fraction x L`, with `L` the measured beat length. `name = v0 until a, then v0 to v1 over a-b` is `--animate name:0:v0,a:v0,b:v1`, and the end value holds by itself; example, C04 with `L` = 10.9 s: `--animate amount:0:0,5.7:0,7.8:0.25 --length 11.9`. Two uniforms are two `--animate` options (C01, C05, C07, C13, C19). A one-frame step (C14) is `--set-at 3.7:flip=-1.0` (or `--steps flip:0:1.0,3.7:-1.0`). A material switch (C03, C07, C13) is `--material-at SECONDS`: C03 starts with no material and assigns `03-lookup`; C07 and C13 switch from the first shader to the second at the time in the table (if the harness only assigns a first material, render the two parts at the same size and fps with the same schedule and join them with ffmpeg at that time). `--time-origin` is not needed: C08's speed does not depend on where `TIME` starts.
- 30 fps. Render at 3840 × 2160 with the Signal Garden SubViewport native-size route (`../_godot-shaders-series/COMPONENT-SPECS.md`). Logical canvas 1280 × 720, except **C15 and C16, whose logical canvas is 640 × 360** (so the pixel readouts 512 x 288 and 288 x 288 are true).
- Stage colour `#D9D5CA`; Forward+; offline fixed tick rate (so nothing here says anything about real-time frame rate). There is no scripted input in this film; every uniform value is scripted, so each `videoLabel` ends "scripted values" (or "still").
- `--kind sprite` makes a Sprite2D whose square is 0.8 of the window height, centered (in a 16:9 window: x 0.275 to 0.725, y 0.1 to 0.9). `--sprite-tex sprite` is the teal test sprite (blob with two cream eyes, transparent padding); `--sprite-tex white` gives the same square when a shader draws everything itself; `--tex pic=sprite` is the same sprite as a texture uniform.
- Output to `runtime/remotion/public/uv-space/` (MP4 or PNG, names as in the lanes).

Probe positions are fractions of the sprite's square (the Lab's "fill-window" mode: a 256 × 256 window with the 128 px sprite at scale 2), so a probe position equals a `UV` value; values are 0..1 floats read from the rendered frame. The stage colour is (0.851, 0.835, 0.792). The sprite's teal is (0.372, 0.639, 0.569) and its eyes (0.980, 0.977, 0.961); the shaders that draw their own colours use (0.37, 0.64, 0.57) and white.

## Harness features this list needs

All in `../_godot-shaders-series/COMPONENT-SPECS.md`; this film adds nothing else:

1. `--animate name:t0:v0,t1:v1,...` (piecewise-linear float schedules; C01 to C19 except the stills). 2. `--set-at SECONDS:name=value` (C14's one-frame step; `--steps` does the same). 3. `--material-at SECONDS` (C03, C07, C13). 4. `--tex pic=sprite|gradient|checker`, `--sprite-tex`, `--size` (here only for the 640 x 360 rect captures), `--kind rect|sprite` as in `lab/runner.gd`, `--renderer`, `--length`. 5. PNG-sequence output then ffmpeg to MP4; a single PNG for C02.

`ShaderLab` must accept a **PNG** for `video` (C02) and keep its result window 16:9 (every capture here is 16:9); its cue `label`s (at most 60 characters) and its one-line `caption` (at most 80) carry the GLOSSARY definitions of TEXTURE, COLOR, length, TIME, fragment and alpha.
