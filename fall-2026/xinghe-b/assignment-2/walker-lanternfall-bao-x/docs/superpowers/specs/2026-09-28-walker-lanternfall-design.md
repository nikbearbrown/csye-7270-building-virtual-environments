## 1. 意图与成功标准

- 交付一个**资源验证切片（asset slice）**：证明生成的美术、音效、音乐能在一个可玩的 Godot 场景中共同工作，而不是完成整款游戏。

## 3. 游戏概念

**两句话**：灯头信使被困在起雾的午夜集市，头顶的灯光是他唯一的武器。撑过 3 分钟，雾就会散去。

**核心循环**：移动走位 → 武器自动开火 → 击杀掉落灯油宝石 → 经验满升级（暂停，3 选 1）→ 敌人加密 → 两把武器满级合成超级武器 → 3:00 胜利或血量归零失败 → R 立即重开。

**设计支柱（草案，写入 CONCEPT 时定稿 3–4 条）**
1. 光即是力量——光的范围与亮度同时表达攻击和安全。
2. 只动脚，不动手——唯一的主动操作是走位，决策集中在升级选择。
3. 静音也读得懂——所有事件都有视觉表达，声音只是加强。
4. 一局三分钟——失败即刻重开，不惩罚尝试。

## 4. 玩法与系统（切片范围）

**操作**：WASD / 方向键 / 手柄左摇杆移动；1/2/3 或方向+确认选卡；Esc/P 暂停；R 重开；M 总静音；9 音乐开关；0 音效开关。朝向左右两向，跟随水平输入，左向由程序 `flip_h`。

**武器（各 3 级）**
- 光束 Beam：沿朝向发射；升级分支：射速 或 穿透。
- 灯蛾 Moth Orbit：环绕角色；升级分支：数量 或 半径。
- 被动（各 2 级）：移速、拾取范围、最大血量。
- **合成**：Beam 与 Moth 均达 3 级后，下一次升级必出"灼日灯塔 Sunflare"卡；选择后两武器合并为周期性全屏光爆，角色切换强化配色，音乐淡入强化层。

**敌人**：飞蛾（快、脆）；雾影（慢、厚、接触伤害）。生成时间表数据化配置，约每 30 s 升一档密度。

**状态**：`menu → playing ⇄ levelup / paused → won | lost → (R) playing`。

**范围外（写入 CONCEPT 作为学期目标）**：更多武器与合成配方、Boss、局外成长、存档、多地图。

## 5. 架构

信号驱动、单一状态来源；每个模块可独立测试。

| 模块 | 职责 | 依赖 |
|---|---|---|
| `game/game_state.gd` | 状态机，唯一状态来源，发出状态信号 | 无 |
| `features/player/` | 移动、朝向、受伤无敌帧、动画状态选择 | tuning |
| `features/weapons/beam.gd`, `orbit.gd`, `sunflare.gd` | 武器行为与等级数据 | player 位置、tuning |
| `features/enemies/spawner.gd` + 敌人场景 | 按时间表生成、追踪、死亡掉落 | 生成表数据 |
| `features/progression/` | 经验、升级卡池、合成判定 | 武器等级 |
| `audio/audio_bus.gd` | **只订阅**游戏信号并播放；冷却、复音上限、合并窗口；音乐闪避/淡出 | 信号（单向） |
| `ui/` | HUD、升级卡、暂停、结算、静音开关 | 状态信号 |
| `features/tuning.gd` | 全部数值 | — |

**关键约束**：`AudioBus` 不向游戏写任何状态；音频流为 null 或静音时逻辑完全一致（由自动化检查 2 证明）。

## 6. 素材管线

**美术**：FLUX.1-schnell（Apache-2.0，经 mflux 在本地 4-bit 运行）→ 一次生成多姿势设定图 → 脚本裁切并缩放到游戏尺寸 → 强制量化到规定调色板 → 人工修补。每类素材生成 3–6 个候选，拼 contact sheet，由 Bao 选择；被拒结果保留缩略图。

**音效**：Stable Audio Open 1.0（Stability AI Community License）本地 → 裁剪、淡入淡出、响度归一 → WAV。

**音乐**：MusicGen（Meta AudioCraft，权重 CC-BY-NC 4.0，课程非商业用途）本地 → 固定 BPM 生成 → 按小节边界裁切 → 首尾交叉淡化、零交叉对齐 → OGG，Godot 中启用 loop。

**禁止**：在世艺术家名、受版权角色、品牌、现有音乐录音、真人声音克隆、未公开 API 密钥。

## 7. 素材清单

**美术**
| ID | 内容 | 游戏尺寸 |
|---|---|---|
| ART-PC-01 | 灯头信使 12 姿势：正/侧/背转身、idle、walk contact、walk passing、施放、受伤、升级欢呼、灼日强化、倒下（失败）、胜利 | 32×32 |
| ART-EN-01 | 飞蛾 2 帧 | 24 px |
| ART-EN-02 | 雾影 2 帧 | 40 px |
| ART-ENV-01 | 石板路无缝地面 | 64×64 |
| ART-ENV-02 | 集市灯笼摊位道具 | 可变 |
| ART-FX-01~03 | 光束、灯蛾、灼日光爆 | 可变 |
| ART-PK-01 | 灯油宝石 | 12 px |

**角色调色板（暂定）**：灯金 `#F2B84B`、光晕米 `#FFF1C9`、外套藏青 `#2E3A59`、挎包棕 `#8A5A3C`、轮廓墨 `#14121C`。碰撞体：20×20 圆，覆盖躯干，不含光晕。

**姿势 → 游戏状态**：idle→站立；walk contact/passing→移动；施放→Beam 开火帧；受伤→无敌帧期间；升级欢呼→levelup；灼日强化→合成后；倒下→lost；胜利→won；三转身→设定表参考。

**音效**
| ID | 事件 | 防重复 |
|---|---|---|
| SFX-01 | 敌人被击杀 | 冷却 60 ms、最多 3 声部、音高 ±5% |
| SFX-02 | 拾取宝石 | 80 ms 内合并为 1 次 |
| SFX-03 | 玩家受伤 | 绑定 0.8 s 无敌帧，每次伤害一次 |
| SFX-04 | 升级 | 每次升级事件一次 |
| SFX-05 | 合成灼日灯塔 | 全局一次 |
| SFX-06a/b | 失败 / 胜利 stinger | 进入结束状态时一次 |

所有 SFX 由状态变化信号触发，与按键无关，故长按/连按不产生重复。

**音乐**
| ID | 内容 | 行为 |
|---|---|---|
| MUS-01 | 夜市主循环，~30–40 s | 一局开始播放；暂停：低通 + −10 dB 继续；升级选卡：−6 dB；失败：0.5 s 淡出 + stinger；胜利：淡出 + stinger；重开：从头 |
| MUS-02 | 同 BPM 强化层 | 合成后淡入，与 MUS-01 同步 |

**静音可读性**：受伤红闪+击退+血条；拾取宝石飞向角色；升级暂停+卡牌；合成横幅+换色；结束结算面板。

## 8. 交付文档与顺序

1. `CONCEPT.md`、`STORYBOARD.md`（≥6 格 SVG 灰盒分镜，16:9，≥3 景别、≥3 角度、≥2 格运动，每格写操作/画面/声音/素材 ID/设计原因）、`CHARACTER-SHEET.md`（生成前放剪影与比例草图）、`CHANGE-BRIEF.md`（≥3 个预计问题 + 验证方法）→ Bao 审阅 → commit 并打 tag **`design-v1`**。
2. 此后原文不改，只在各文档底部 "Revisions" 区追加带日期的修订。
3. `ASSET-LOG.md`：每次重要生成记录 ID、模型与版本、本地运行、许可、完整 prompt/negative、seed/尺寸/时长/设置、接受/修改/拒绝及原因、手工修改、文件路径、分镜；时间戳须晚于 `design-v1`。
4. `SOURCES.md`、`TEST-REPORT.md`、`FRICTIONAL.md`、`README.md`、视频 beat sheet/脚本/提示词、`SUBMISSION.md`。

`.gitignore` 允许 `*.wav` / `*.ogg`（游戏音频），排除 `.godot/`、`*.mp3`、`*.mp4`、>25 MB 文件、凭据、模型权重。

## 9. 测试

**自动化（Godot headless，输出 JSON 证据到 `evidence/`）**
1. 状态机转换：升级暂停、胜利、失败、重开。
2. 声音不决定状态：音频流全置 null 跑固定种子一局，结果与有声一致。
3. 防重复：模拟连按/长按 100 帧、同帧 20 次击杀、连续拾取，统计每个 SFX 实际播放次数。
4. 精灵调色板：所有像素属于规定色值，尺寸正确。
5. 音乐循环接缝：循环点采样跳变与 RMS 空白阈值。
6. 仓库卫生：无 MP3/MP4、无 >25 MB、无 `.godot/`、文档中的素材 ID 均有文件。

**人工（必须由 Bao 本人）**：有声一次、静音一次完整试玩；记录角色 vs 设定表、分镜 vs 实机对比截图；至少一次"观察问题 → 修改素材/提示/循环点/配色 → 重新验证"。

## 10. 视频

使用 `godot-gamedev` skill + walker modifier（**不是** godot-waikthrough），4K 横屏，Walker 开场/总结 + Verdict → Your Turn → regular outro。覆盖作业第 7 节 10 项内容；追踪的单一素材建议为 ART-PC-01（设定草图 → prompt → 原始输出 → 量化/修补 → 游戏内）。含一段无旁白的纯游戏声音片段。视频文件不进 git，README 写文件名、链接、SHA-256。

## 13. 风险

| 风险 | 缓解 |
|---|---|
| 生成角色帧间不一致 | 单图多姿势 + 调色板锁定 + 剪影检查；不足时对单姿势重生成并记录 |
| 16 GB 内存跑 FLUX/音频模型吃紧 | FLUX 4-bit 量化；模型串行运行；必要时降分辨率 |
| MusicGen 输出节奏漂移，难以无缝循环 | 生成多条候选，节拍检测选稳定段，交叉淡化 + 自动接缝检查 |
| 自动攻击导致音效刷屏 | 音效只绑定击杀/拾取等状态事件并限流；检查 3 验证 |
| 时间不足 | 10/4 为缓冲；必要时砍 ART-ENV-02 与 SFX-06 |
