# walker-survival-shooting — Assignment 5

A third-person 3D extraction shooter. The player lives in a subway base, carries a rugged military tablet, goes out to fight monsters and extracts. This assignment (Assignment 5) adds two hand-written shaders and the materials that use them: the tablet screen lights up when the tablet reaches the hand, and the two weapon crates show worn, chipped paint with rust underneath.

## Starting point and versions
- **Starting point:** my Assignment 3 project (course repository `assignment-3/`, tag `a3`), plus the character body/brain and tablet logic written after it (the first Assignment 5 upload).
- **Godot:** 4.7.2-stable (Windows), renderer **Forward+** (`config/features` in `project.godot`), D3D12, Jolt Physics.
- **Claude Code:** Claude Opus 5.5.

## How to run
1. Open `godot/project.godot` in Godot 4.7.2; import once first: `godot --headless --path godot --import`.
2. Run the main scene `base.tscn` (F5).

**Controls:** WASD to move, Shift to sprint, Space to jump, right mouse button to aim, **Tab** to take out / switch / put away the tablet. Short press: hip → one hand, one hand → hip, two hands → one hand; long press (0.4 s): hip or one hand → both hands in front of the eyes, two hands → hip (`_next_tablet_hold()` in `humanoid.gd`).

**Seeing the effects:**
- Screen glow: press Tab to take out the tablet; the screen lights when the tablet reaches the hand (0.35 s) and goes off at once when it is put away.
- Crate wear: the two weapon crates by the back wall of `base.tscn`. The long crate `crate_long` is heavily worn (about 23% rust), the small crate `crate_cube` lightly (about 10%).
- Hint experiment: open and run `experiments/hint/hint_experiment.tscn` (F6). The upper quad samples with `source_color`, the lower one without.
- Capture tool: `debug/screen_glow_capture.tscn`; while holding the tablet in both hands press F9, and it saves one engine capture each at 0 / 0.39 / 1.0 / 2.0.

## How to run the tests
Every test runs through `scripts/run-test.sh <test file> <fps>`. It adds a timeout, pins the frame rate, keeps a log in `logs/`, and fails on `SHADER ERROR` / `SCRIPT ERROR`. On Windows, first set `GODOT` to the path of the Godot console executable.

```bash
./scripts/run-test.sh a3_asset_check.gd 60
./scripts/run-test.sh screen_glow_check.gd 30
./scripts/run-test.sh screen_glow_check.gd 60
./scripts/run-test.sh screen_glow_check.gd 144
./scripts/run-test.sh normal_map_check.gd 60
./scripts/run-test.sh test_materials.gd 60
```

Expected results (2026-11-01): 55 / 24 / 24 / 24 / 2 / 169 PASS, exit code 0 for all. Details in `TEST-REPORT.md`.

## What this assignment added
- **Screen-glow shader** `godot/shaders/pad_base_light.gdshader` (hand-written by me): `unshaded`, uniforms only, no textures. The driver sets `pad_light_data` from the tablet's state; it becomes 0.39 when the tablet reaches the hand. Each tablet's material has Local To Scene ticked, so tablets do not affect each other.
- **Crate wear shader** `godot/shaders/crate_wear.gdshader` (hand-written by me): samples one colour texture (the rust, with `source_color`) and one data texture (a height mask, without it); rust shows in the low places first. The models have no UVs, so `vertex()` makes a box projection from the normal direction. 5 parameters in 3 groups (`paint`, `wear`, `mapping`).
- **Two materials** `godot/assets/furniture/materials/crate_long_wear.tres` and `crate_cube_wear.tres`: the same shader, different `wear_amount` and `paint_roughness`; attached to the crate shells through Use External in the two `.glb` import settings.
- **Hint experiment:** `tools/make_hint_greys.gd` writes the 3×1 grey PNG (64 / 128 / 192); `godot/shaders/hint_experiment.gdshader` (hand-written by me) and the two materials and scene are in `experiments/hint/`.
- **Step 4:** `godot/shaders/standard_generated.gdshader`, generated by the editor from a StandardMaterial3D, annotated by me; the game does not use it.
- **Textures:** Metal041C from ambientCG (CC0); see `godot/assets/shader/metal041c/ATTRIBUTION.md`.
- **Tests:** `tests/screen_glow_check.gd` (the driver, at 30 / 60 / 144 fps), `tests/normal_map_check.gd` (the normal-map curl check), `tests/test_materials.gd` (the material audit).
- **Documents:** `CLAUDE.md`, `CHANGE-BRIEF.md`, `godot/MATERIALS.md`, `LANGUAGE-NOTES.md`, `TEST-REPORT.md`, `../FRICTIONAL.md`, `SOURCES.md`; captures in `captures/`, logs in `logs/`, prompts and session excerpts beside them.

## Known limitations
- The crate shader does not write `METALLIC`: the silver scratches in the rust are shaded as non-metal (found by the audit; I decided to keep it).
- When the tablet moves straight from the hip to the two-hand position, its path passes through the body.
- The tonemap (Linear), exposure (1.0) and glow off in the hint scene and `base.tscn` are `Environment` defaults; Godot does not write defaults into scene files, so the test reads the runtime values.
- The normal-map source files are 16-bit but decode to 8-bit, so the curl ratio is 0.199 rather than 0.
- The "edit one shader line and both crates change" check was not done (TEST-REPORT section 9).
- The game has no pause yet, and no playable combat or extraction yet.
