# 地图与场景改造：地形组织半线性道路

本次落实用户要求：参考《恐怖黎明》的关卡组织方式，以连续地形绘出前进道路。沿用现有拉普兰德像素角色、PRTS 参考敌人及场景素材，不改变外勤合同和单向区段规则。

## 参考依据

- [Crate 官方探索指南](https://www.grimdawn.com/guide/gameplay/exploration/)：世界总体布局经过手工设计，局部障碍、目标和遭遇带有随机性；支路、隐藏区域和奖励支持探索。
- [官方 Modding Guide](https://www.grimdawn.com/downloads/Grim%20Dawn%20Modding%20Guide.pdf)，印刷页 10–15、21：地形高度、坡道、地表纹理、禁行区和导航检查是明确的不同工序。
- [官方截图页](https://www.grimdawn.com/media/)中的 [Howling Chasm 截图](https://www.grimdawn.com/wp-content/uploads/sites/3/2019/06/2019-03-GDX2_09.png)：实际查看道路、崖壁、深渊和入口的关系。我的观察是：可通行面的轮廓及其高差先把方向讲清楚，装饰再补充地点信息。此项是截图分析，不是开发者原话。

应用到本项目：主路始终连通，奖励支路有明确用途。

**2026-09-29 起，手写骨架已被开凿式随机生成取代**，改按《贪婪洞窟》`level_N.plist` 的组织方式配置——尺寸区间、两个转向几率因子、各类元素的 {min,max} 数量预算，详见 `贪婪洞窟地图设计调研.md`。节点纵深、横向、数量（11~17）、房间大小、支路条数与锚点、岩柱、环路、壁龛、捷径、密室位置全部由种子决定。唯一保留的约束有二：主干朝向限制在向北的锥形内（单向推进是硬性规则，且这保证主干不自交、连通性由构造成立），以及每三分之一路段至少一条支路（装置按支路深度排序分配，否则某些种子会把撤离点甩到地图前段）。

## 连接处的过渡

走廊与战斗空地原本以硬并集（`max`）拼合：一条 5 宽的走廊撞进 14 半径的圆形空地，两条边界以夹角相交，交界处留下可见的折角缺口，折线走廊的拐点内侧同理。现改为**多项式平滑并集**，在每个接缝自动生成圆角过渡——走廊汇入房间时张开成喇叭口，拐点内侧收圆，无需逐个接缝手工处理。岩柱改用平滑差集，只抹掉冲切般的硬边，仍保持是独立物体。

只混合**距离最近的两个形状**，不对整条形状链逐个折叠。逐个折叠时每一步最多增厚 k/4，而只有当两个操作数相差超过 k 时该步才会停止贡献，于是任何"多个形状距离相近"的位置都会按附近图元的数量增厚——这不是布局应该具备的性质。倒角本来就只涉及构成该接缝的两个面，取最大与次大即可得到同样的圆角，且上界固定。

混合半径 3.5，明显小于并行路线之间的间距，避免仅仅彼此靠近的形状被融成一团、破坏空地与走廊的宽窄对比。改动后三地可走面积占比 25% / 26% / 28%（改前 24% / 24% / 27%），增加的部分即倒角本身。

## 地区表现和路线节奏

- 矿区：弯曲采掘通道、凸起矿体、独立掩体岩柱，磨损带和双轨标识主路；源石矿簇位于路外矿床。
- 街区：折向街巷、较方正的交叉口和广场，连续废墟台地界定街区；破损道路标线沿主路延伸。
- 雪原：较宽的谷道与战斗空地、连续积雪坡岸、冷色冰冻路面；林木和岩块位于谷道外侧。

从入口沿主路依次经过收窄口、战斗区、交汇处和终点。四条奖励岔路分别容纳强化、补给、点金、撤离；没有撤离点时该岔路仍有补给。部分种子生成一个局部回环及对应补给。补给按实际奖励位置全部生成，目前每段 5–6 处；这是避免空支路的实现调参，后续可结合掉落价值平衡。

## 立体分层与出口随机（2026-10-12）

用户要求：模糊主路和支路的区别；出口随机刷新，不一定在主路尽头；参考《恐怖黎明》做上下层立体地图。

### 主路与支路不再可辨

主干仍是生成时的骨架（保证单向推进与连通），但玩家从地面上读不出来：

| 以前的区分线索 | 现在 |
|---|---|
| 主干走廊 5–6.2 宽，支路 3.2–4.2 | 所有走廊同一分布 3.4–5.6（雪原 +0.5、街区 +0.3） |
| 支路尽头一律 6–8.5 的小房间 | 支路房间 60% 小房间、40% 10–13.5 的战斗空地 |
| 支路与主干垂直分出 | 分叉角 43°–100°，有的顺着前进方向斜出 |
| 支路只有一间 | 40% 的支路再延伸出第二间 |
| 矿轨/路面标线/路面磨损只铺主干 | 每条走廊单独掷：主干 70%、支路 45% |

### 出口位置

「深入入口」（三条路线标记）从地图上所有死路房间里选：步行距离在全图最远者的 50% 以外、半径够放三个标记即可。主干尽头只是候选之一，抽中概率压到 25%。30 个种子里 12 次落在主干尽头。撤离点另从远端死路中选，与入口至少相距 25。据点头目改守通往入口的那间房间（`route_guard_position`），不再固定在主干倒数第四个节点。出口不在主干尽头时，尽头房间补一处补给。标记沿来路方向横排。

### 台地分层

- 三层台地：0 / 2.2 / 4.4（`TIER = 2.2`，`MAX_TIER = 2`），入口在第 0 层。
- 房间整体平整，处于整层高度。走廊连接不同层的房间时就是坡道：两端各留 2 的平台，坡长每层至少 6.5（约 19°，远低于导航 35° 和角色 45° 上限）。街区坡道铺台阶，矿区铺枕木；雪原坡道不铺东西。
- 两块不同层的地面相邻但没有坡道相连时，交界处是悬崖：沿半层高度切开，两侧地面保持平整直到崖边，中间立垂直岩面，并加碰撞墙。高处走不下去，低处爬不上来，射线被挡。崖脚有阴影，崖顶边缘提亮，高层地面整体略亮，正常镜头里能读出层次。小地图把崖线画进轮廓。
- 可走地面仍是 x/z 平面上的单层（没有桥从另一条路上方跨过），所以迷雾、小地图和所有可走性判断都不用改成三维。真正的上下重叠（桥、地下层）是下一步的事，需要另外拍板。

### 层级如何定

层级不是盲掷，而是按几何约束分配（`ContinuousWorldMap._assign_levels`）：

1. 每条走廊拆成三段：起点平台、坡道段、终点平台。
2. 若一个形状伸进另一形状的中线（不只是擦边），两者必须同层，否则崖线会横切通道。这类形状用并查集合成一组；放不下坡道、或坡道段旁有别的形状的走廊，两端房间也并为一组。
3. 只在组与组之间、且一定是能放坡道的走廊上升降一层。主干上为坡道特意挖长的那一步必升降，支路按 45% 掷。
4. 采样后用三角网格做一次连通检查（只走坡度不超崖阈值的三角形）。不通就重掷一次，再不通才全图放平。30 个种子里 1 次放平。

### 玩法连带改动

- 敌人移动、出生、驻防站位都贴地面高度（`Enemy.GROUND_LIFT`）；预警圈、燃烧瓶、地面危害、遗物箱、地图标记同样贴地。
- 视线检测从各自地面以上 0.7 起算；鼠标点地沿台地迭代求交。
- 角色普攻与扫击不打高差超过 1.6 的敌人（`Player.TIER_REACH`），站在崖上不能隔崖砍崖下。
- `nearest_walkable` / `teleport` 约定：低于当地地面的 y 视为「离地高度」，因此原有按平地写的 `y = 0 / 0.5 / 0.7` 调用不用改。
