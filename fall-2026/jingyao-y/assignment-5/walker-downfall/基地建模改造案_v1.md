# Downfall · 罗德岛基地建模改造案 v1（草案）

2026-10-18。用户提出：基地也改成建模，不再用贴图拼，材质贴图找 Sol 要。

**拍板（用户 2026-10-18）**：先做大厅看效果；H1–H4 的像素图不再用；H5/H6 作废，改为材质需求。

## 一、现状

- 基地共 5 个房间：大厅、仓储区、医疗部、商店、武器库，全部是 2D 像素拼图（`world/base_map.gd`、`art/rhodes_runtime/room_*.json`）。每个房间由三层组成：
  - **地面**：一整张平铺图，地板、贴花、光斑、墙顶都画在里面；
  - **北墙**：一张正对镜头的立面图；
  - **道具**：154 个摆件，每个是一张面向镜头的像素图，一共用到 72 张不同的图，都是 Sol 的 H1–H4 批次。
- 局内地图早就是 3D：Blender 模型套件，加 `FieldLight` 光照图，再加 Sol 手绘的材质（龙门 C1–C9、叙拉古 S1/S2）。
- 所以基地和局内的观感不统一：
  - 局内的东西有体积、有光影，基地是平的；
  - 基地的人物和道具靠“脚底对齐”排前后，墙挡住人时靠棋盘格镂空。

## 二、做法：和局内地图同一条路

| 层 | 现在 | 改成 |
|---|---|---|
| 房间壳体（地板、墙、门洞、天花梁） | 地面图 + 北墙立面图 | Blender 建的舰船内舱壳体，按房间尺寸拼模块（地板块、墙板、转角、门框、柱、管线） |
| 道具 | 154 个面向镜头的像素图 | 3D 模型。72 张图归并成约 35 个模型，同类共用一个模型换材质，例如货架、终端、病床、柜台、箱子、吊灯 |
| 光 | 画死在图里的光斑和 `base_room_light` | 用局内的 `FieldLight` 思路：灯位写在房间数据里，加上环境光。仓储区逐排亮灯的效果保留 |
| 墙挡住人 | 棋盘格镂空 | 沿用局内的做法：挡住干员时把墙半透明或切掉 |
| 材质 | 像素图本身 | 先用我程序烘焙的材质，Sol 交手绘材质后替换（见第四节） |

**不变的东西**：
- 房间布局、碰撞、交互点、出生点、货架格子（`cells`）全部沿用 `room_*.json` 的坐标。玩法代码只换显示层，不改逻辑。
- 这些代码要逐个确认：`base_markers.gd`、`warehouse_view.gd`、`room_reveal.gd`、`game_manager` 里的基地部分。

**需要重做的动态效果**：
- 仓储区个人货架“升起”和闸门开合（现在是 6 帧图，`shelf_hatch`），改成模型位移动画；
- 进仓储区逐排亮灯；
- 医疗部病床有人和没人两种状态（H5 里要求的，现在没有）。

**H5、H6 的处理**：这两批是还没交的平面道具（仓储部件、医疗部件、加工站、交易所终端）。改成建模后它们直接做成模型，**H5、H6 的平面出图需求作废**，改为材质需求并入第四节。

## 八、全息沙盘与罗德岛的位置（2026-10-18）

**用户原话**：“沙盘应该更大，调研泰拉大陆的分布”，以及“沙盘改成经典的、在全息沙盘上显示的蓝色数字罗德岛，罗德岛不用很大，然后罗德岛放在泰拉大陆沙盘某处，表示罗德岛在此位置，正好和运送、收取物资、和派系改善关系等内容联动”。

**调研**：见 `泰拉地理调研_v1.md`。PRTS 打不开，坐标取自 wiki.gg 社区重绘的泰拉地图，目测误差约 ±0.02，表里逐条标了可信度。

**已做（只有表现，不改数值）**：
- **沙盘台**：放在大厅东侧 (104, −33)，15 × 11 m，深色发射板，四角是投影头，边上一圈发光导轨。
- **全息地图**：泰拉大陆以叠加发光的方式投在台面上方，带扫描线和轻微闪烁（`world/base_hologram.gdshader`）。内容包括海岸线、内海和湖、各国边界（按各国中心点划分）、谢拉格山脉、冰原、沙漠和北方迷雾，不写任何文字。
- **数据与生成**：地图数据是 `art/kit/textures/terra_map.json`，图片由 `tools/blender/base/make_terra_map.py` 生成。
- **罗德岛标记**：约 1.5 m 长的蓝色全息小舰，悬在所在地上方，缓慢旋转、上下浮动，脚下有一圈扩散的光环。
- **罗德岛在哪**：
  - 位置存在 `BaseState.ship_at` 里，随存档保存，新存档默认在龙门附近。
  - 每次出发执行合同，罗德岛就开到那个地区：矿区对应切尔诺伯格，龙门对应龙门，萨米对应萨米，叙拉古对应叙拉古。
  - 回到基地时，沙盘上的标记会显示在新位置。

**联动提案（待拍板，还没改任何数值）**：
1. **托运和远程交易**：罗德岛离派系所在国越近，企鹅物流的托运费和交易所的远程手续费越低，比如同一国 ×0.5、相邻国 ×0.75、远方 ×1.25。派系的所在国用 `FactionCatalog` 里已有的 `region` 字段。
2. **收货**：投保物品送回所需的现实时间按距离缩放，比如同一国用下限 2 小时、远方用上限 4 小时。加工部的外部订单也可以用同样的规则。
3. **派系关系**：卖货给所在国就在附近的派系，关系增长 ×1.5；在远方则 ×0.75。舰在某国境内时，那里的局内据点更容易出现。
4. **主动航行（可选，改动大）**：在沙盘台按 E 选择目的地，罗德岛开过去要花现实时间，期间不能出发执行合同。这样位置本身就成了一项要权衡的决策。

## 九、3D 全息地形沙盘（2026-10-18）

**用户原话**：“中间应该是罗德岛的标志；地图应该更细致，建模城市、山地等地形，要3D立体的全息投影，沙盘可以更大，展示更多细节”，以及“根据各地区的地形建模”。

**标志修正**：之前地面和模型上的标志，误用了遭遇点那套带医疗十字的三角。现在全部换成 Sol 的 L 版罗德岛标志：三角里一座城堡塔，`art/kit/textures/base_rhodes_logo.png`。地面嵌花取标志的浅色部分，三角框和塔显示为浅色，其余是甲板本色。

  | 炎 | 丘陵、南北向大河 |
  | 东国 | 海岸山地 |
  | 卡西米尔 | 平坦草原 |

  | 维多利亚 | 低盆地、河谷 |

  | 谢拉格 | 高耸破碎的雪山 |
  | 米诺斯 | 山地 |
  | 哥伦比亚 | 阶梯状台地 |
  | 玻利瓦尔 | 雨林、黑流大河 |
  | 萨尔贡 | 西部沙丘、东部雨林、大河三角洲 |

  因菲冰原是一块抬升的高原，河流会切出河谷。
- 森林按各国的林地比例散布成小树，共 457 棵。各国首都是塔楼群；龙门、切尔诺伯格、卡兹戴尔是带履带平台的移动城市。

- 罗德岛标记悬停在所在地的地形高度之上。

**踩过的坑**：
- Godot 的 OBJ 导入器只有在面同时带法线时才保留 UV，所以要写 `f v/vt/vn`；V 方向会被翻转，所以写入 `1 − v`。
- 地图要按原始数值采样，不能加 `source_color`，否则陆地的蓝色在线性空间里会暗得看不见。

**全息巨幕**
- 24×6.2 m，悬在两根发射塔之间，下方是地面发射轨。屏幕向镜头后仰 42°，站在交易台之间就能看到整块屏。

  - 左侧：龙门币/赤金 K 线，带 MA5、MA20 和成交量，标出最新价和当日涨跌。数据不满一天时自动改用 1 分钟 K 线。

- 只有数字、箭头和颜色块，没有文字（场景里不挂文字）。配色沿用游戏内 K 线：绿涨橙跌。
- 实现：画进 `SubViewport`，再用全息着色器以叠加光的方式显示（`base_hologram.gdshader` 新增 `uv_scroll` 参数用于滚动）。只在基地显示时才渲染。

**交易大厅建模**
- 交易员工位（`trader_desk`）×5，分两排面向巨幕：2×3 显示器阵列、两副键盘、交易电话、座椅、紫色边灯。
