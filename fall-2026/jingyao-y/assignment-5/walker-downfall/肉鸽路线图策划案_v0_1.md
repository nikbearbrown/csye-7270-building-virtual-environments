# 肉鸽路线图策划案 v0.1

2026-10-24。用户看了现在的“选择去向”界面（入口 → 物资作业面 → 下一层三选一），觉得太单调，要“设计更多类型节点，像明日方舟肉鸽那样随机地图”。本案把每 10 层改成一张**集成战略式的分支路线图**，并给出节点类型清单。

本案只做设计，不改代码。等用户拍板（§9）后再实现。

---

## 1. 现状（读代码核对）

| 项 | 现在的做法 | 位置 |
|---|---|---|
| 去向种类 | 只有 3 种，永远同样 3 个：巡检支路（危险 −3、掉落 +0%）、物资作业面（0 / +25%）、深部污染带（+5 / +50%） | `FieldCatalog.ROUTES` |
| 出口 | 每层出口房间里固定摆 3 个路标，一个路标对应一种去向；走到哪个路标按 E，界面就预选哪个 | `ContinuousWorldMap` 2156–2168 行、`_interact` |
| 去向的作用 | 只有一个 `route_index`（0/1/2）：难度修正、敌人数 `9 + route_index×3`、深部多一个精英、宝箱上守卫、深部加污染/寒冷、掉落加成 | `game_manager.gd` 2742、3723、3824、3876、4023、5159 行 |
| 层内随机内容 | 每层各自掷骰，玩家进层前完全看不到：罗德岛小队 30%、坎诺特 20%、空位上势力据点 40%、密室 28%、踪迹 20%、萨卡兹哨兵 10%；随机撤离点在区段第 4–6 层合计 50% | `_roll_encounter`、`_roll_random_extraction`、`VAULT_CHANCE`、`RecruitCatalog.TRACE_CHANCE`、`ThreatMeter.SENTINEL_CHANCE` |
| 每层都有 | 强化装置（三选一藏品）、出口守卫 | `_offer_builds` |
| 区段节奏 | 第 10 层是据点（守卫者；每 20 层是 Boss 战场），出口要等头目倒下才开；然后是营地（不算一层）；选好的去向存进 `_camp_route`，出营地时用 | `is_outpost_floor`、`advance`、`_enter_camp`、`leave_camp` |
| 界面 | 左边最近三层（已走）→ 当前层 → 三个去向 → 一个灰色“—”；右边是名字、一行描述、掉落加成、前进 | `event_screens.gd` `routes()` |
| 局内存档 | 存 `route_index`、`route_history`、`_camp_route` | `run_save.gd` `GAME_KEYS` |

**为什么单调**：三个选项每层都一样，选的只是“难度旋钮”；真正有意思的东西（商人、小队、密室、踪迹、撤离点）都是进层后才掷出来，路线选择和它们没有关系，玩家没法“为了某个东西规划一条路”。

## 2. 设计目标

1. **能规划**：进入一个区段就能看到这 10 层的整张图，为了商人、安全屋、密室、撤离点去绕路，是这次改动的核心。
2. **每张图都不一样**：节点种类、分叉数、汇合位置每次随机。
3. **用已有系统落地**：节点只是把现在“进层后才掷骰”的东西提到图上（坎诺特、罗德岛小队、势力据点、密室、踪迹、撤离点、强化装置、精英、Boss），再加少量新内容（不期而遇事件、地区特色节点）。
4. **不破坏现有节奏**：每 10 层一个营地、第 10 层据点/Boss、随机撤离点 50%、掉落阶梯、威胁值都保留。

## 3. 路线图结构

### 3.1 一张图 = 一个区段（10 层）

```
           列1     列2     列3     列4     列5     列6     列7     列8     列9     列10      
 区段1：  [入口] ─┬─[巡]──[商]─┬─[物]──[遇]──[密]─┬─[恶]──[安]──[物]─┐                    
                 ├─[物]──[遇]─┘     ├─[深]──[撤·物]┘ ├─[遇]──[藏]──[深]─┼─[守]──▶ 营地 10|11 
                 └─[深]──[物]──[势]─┴─[物]──[巡]────┴─[巡]──[物]──[遇]─┘                    
```

- **列 = 层**。区段 1 的列 1–10 就是第 1–10 层；区段 2 是第 11–20 层，以此类推。
- **列 1**：
  - 合同从第 1 层出发：列 1 只有一个节点“入口”（普通作战层，和现在的第 1 层一样）。
  - 其他区段（从营地出来）：列 1 有 2–3 个节点，在营地里选。
- **列 2–9**：每列 2–4 个节点（权重 2 个 25% / 3 个 50% / 4 个 25%）。
- **列 10**：只有一个节点：据点（守卫者）或 Boss 战场（每 20 层），和现在一样。所有列 9 的节点都连到它。
- **列 10 之后是营地**，不算一层，不在图上占列，只画在最右边作为终点。

### 3.2 连线规则（分叉与汇合）

参照集成战略和《杀戮尖塔》的做法：

1. 每个节点向下一列连 **1–2 条线**（1 条 60%、2 条 40%），只能连到“相邻行”（按纵向位置归一后，行号差 ≤ 1），**线不交叉**。
2. 下一列每个节点**至少有一条线进来**；上一列每个节点至少有一条线出去。没有死路。
3. **汇合点**：列 5 或列 6 中随机一列压成 **1–2 个节点**（瓶颈），让不同路线在中段汇到一起，保证随机撤离点和关键节点大多数路线能碰到。
4. 列 9 → 列 10 全部汇合。
5. 同一节点连出的两个下一列节点**类型不同**（避免“二选一但两个一样”）。

### 3.3 能看到多少

- **整张区段图在进入区段时就生成并全部可见**（和集成战略一样：一层的图一开始就看得到）。节点类型都显示，“不期而遇”显示为“？”，进去才知道是哪个事件。
- **下一区段看不到**：图的最右边只画“营地”。到了营地才生成下一张图。
- 已走过的路线实线、当前位置纸白色、能走的下一列节点亮显、走不到的节点变暗（不隐藏，方便看全局）。

### 3.4 生成时机与种子

- 区段图在**合同开始**或**进入营地**时生成，种子 = `_run_seed + 区段号 × 104729`，用独立的随机数生成器，不消耗 `rng`，所以局内存档重建一层时不受影响，同一种子同一张图（方便测试）。
- 合同从营地出发时，营地里直接生成下一区段的图。

### 3.5 层内的出口

- 出口房间里的路标数 = **当前节点连出的线数（1–2 条，据点之前 1 条）**，不再固定 3 个。
- 路标模型按节点类型换颜色（与图上节点底线颜色一致），**不挂文字**（交互只提示 E）。走到哪个路标按 E，打开路线图并预选那条线，和现在一样。
- 据点层（列 10）只有一个路标，通往营地。
- 营地里的“继续深入”打开下一区段的图，选列 1 的节点。`_camp_route` 改为存这个选择。

## 5. 不期而遇事件

### 5.1 怎么玩

- 节点在图上显示“？”。进层后地图较小（尺寸系数 0.7），敌人数 ×0.6，有强化装置。
- 地图中段有一个事件物件（模型按事件换）。走近按 E 打开事件卡。
- 事件卡：**事件名 + 2–3 个选项**；每个选项只写“代价 → 收获”的数据（例：`生命 −20% → 藏品（高）`、`赤金 −3 → 下一层威胁值 0`），不写剧情说明（遵守“界面不写说明文字”；能不能加一句台词见 §9 第 5 条）。
- 选一个就结算，事件物件消失。不选也能离开这一层。

### 5.2 事件池（第一批 16 个）

通用（四个地区都有，按地区换模型和名字）：

| 废弃的强化装置 | 生命 −25% → 藏品三选一（中/高） ／ 离开 |
| 受伤的感染者 | 一瓶急救剂 → 本地区势力关系 +10 ／ 赤金 −2 → 踪迹线索 +1 ／ 离开 |
| 补给箱残骸 | 触发一组守卫（2 精英）→ 补给箱（药剂 ×3） ／ 离开 |
| 赌徒 | 赤金 −3 → 50%：赤金 +8；50%：无 ／ 离开 |
| 来历不明的信号 | 下一层威胁值从 60% 开始 → 下一层多一个藏品箱 ／ 离开 |

## 6. 和现有系统的衔接

### 6.1 合同目标

| 合同 | 衔接 |
|---|---|
| 深入 | 不变（按层数算）。 |
| 回收 | 物资作业面节点上目标材料掉率 +50%；图上不额外标。 |
| 猎杀 | 悬赏目标所在列**保底一个险路恶敌节点**，悬赏目标就是这个节点的恶敌；节点画红色外框。没走到那个节点 = 错过，玩家自己选。 |
| 搜索 | 本区段**保底一个密室层**。 |
| 寻访 | 目标列保底一个踪迹节点（必定是目标干员的踪迹）。 |
| 运送 | 交货层（合同里的 `floor`）保底一个该势力的势力据点节点。交货层在别的区段时，到那个区段生成图时再放。 |

保底节点放在“从入口出发所有路线都能到”的位置上不现实，所以规则是：**保底节点所在的那一列，至少一半的上一列节点能连到它**（生成时调整连线）。

### 6.2 随机撤离点

- 规则不变：每区段最多一个，落在第 4–6 层，合计 50%，每层 1/6。
- 区别：**进区段生成图时就掷**，掷中就在那一列**所有节点**上挂撤离信标标记（不是只挂一个节点，保证哪条路线都能用到，概率统计不变）。
- 层内撤离点的位置仍随机、仍被战争迷雾遮挡，走近才显示在小地图上；图上只告诉你“这一层有”。
- 第一次走到第 5 层必有撤离点（`first_extract_given`）：生成区段 1 的图时列 5 全部挂标记。首次外勤锁（`first_run_lock`）不变。
- 科研“撤离保障”：每区段必有，三层各 1/3，同样在生成时掷。

### 6.3 层内随机遭遇（`_roll_encounter`）

节点把一部分随机内容固定下来，原来每层的随机掷骰相应改：

| 内容 | 现在 | 改后 |
|---|---|---|
| 坎诺特 | 每层 20% | **只在“商”节点出现**，作战层不再随机出现 |
| 罗德岛小队 | 每层 30%（食堂 40%） | 作战层保留随机，降为 20%（食堂 27%）；安全屋必定有 |
| 势力据点 | 空位 40% | 作战层空位降为 20%；“势”节点必定有 |
| 密室 | 28% | 作战层保留 28%；“密”节点必定有 |
| 踪迹 | 20%（按深度衰减） | 作战层保留；“踪”节点必定有 |
| 萨卡兹哨兵 | 10% | 不变，非战斗节点（安/商/宴/市）不出 |

科研“商队联络”（第 3 层保底坎诺特）改为：区段图保底一个“商”节点在列 3。

### 6.4 威胁值

| 节点 | 威胁值 |
|---|---|
| 作战（巡/物/深/恶/密/踪/势/矿/火） | 正常累积 |
| 不期而遇 | 正常累积（小地图，自然更快离开） |
| 坎诺特 | 照涨（和现在一样，在他附近也涨） |
| 安全屋、家族宴会 | 不涨；进入下一层时**不继承**（清零） |
| 下城黑市 | 进图从 50% 开始 |

### 6.5 难度与掉落

- `route_index` 换成**当前节点的数据**（类型、难度修正、掉落加成、敌人数系数、精英数、污染/寒冷修正）。原来写死的 `route_index == 2` 判断改成读节点上的字段（“深部”字段）。
- 隐藏难度公式 `B = 3.5 × (层 − 1) + 节点修正`，巡/物/深 的修正保持 −3 / 0 / +5；其他节点：遇 −2、商 −3、安 不刷怪、藏 +2、恶 +3、密 0、踪 0、势 0、地区特色按 §4.3。
- **掉落阶梯不变**（按层深度，16 级只升不降）；节点只改“掉落加成”这一个乘区（`loot_ctx().reward`）。

### 6.6 藏品与强化装置

- 作战节点保留每层一个强化装置（三选一）。
- 非战斗节点（商/安/宴/市）**没有强化装置**；不期而遇有。
- 得偿所愿的藏品箱走 `RelicCatalog.roll_offers`，加一个 `min_rarity` 参数只抽中/高。

### 6.7 地图生成

- 非战斗节点和不期而遇用**小地图**（尺寸系数 0.6–0.7；现在是 1.0–1.5 随机）。`ContinuousWorldMap.generate` 需要接受一个尺寸系数上限。
- 安全屋：不刷怪、不生成出口守卫、营火放在出口房间旁边。
- 遭遇点（`encounter_position`）现有，商/安/势/宴/市都放在这里，不新开位置。

### 6.8 局内存档（`RunSave`）

`GAME_KEYS` 加：

| 键 | 内容 |
|---|---|
| `route_map` | 当前区段图：`{"block": 区段号, "columns": [[节点…]…], "edges": [[[下一列索引…]…]…]}`；节点 = `{"type", "event"（不期而遇的事件 id）, "beacon"（撤离信标）, "contract"（保底标记）}` |
| `route_node` | 当前所在 `Vector2i(列, 行)` |
| `event_done` | 当前层事件是否已结算 |
| `threat_reset_next` | 下一层威胁值是否不继承（安全屋/宴会） |

`route_index` 删除，`route_history` 保留（HUD 小地图在用），`_camp_route` 改存列 1 的行号。区段图在生成时一次存下，不重掷，所以读档后图不变。
